# 可观测性与开发工具

日志、诊断、支持流程、DebugAction 或游戏内检查工具相关任务使用本参考。

## 可观测性契约

诊断应能回答：

- 使用了哪个版本、游戏构建、依赖集合和功能配置；
- 哪个生命周期阶段成功或失败；
- 哪些可选集成被发现、激活、跳过或降级；
- 哪条 Patch、转换或迁移规则影响了故障对象；
- 当前状态是权威、待确认、降级还是已恢复。

在所有权边界和状态转换处记录，不要每 Tick 记录。保留异常和相关稳定标识，避免密钥、完整存档载荷和无界对象转储。

## 限流但不失明

重复失败需要限制输出，但限流本身有生命周期：

- 选择 Key：故障类型加有意义的所有者/Def/Patch 身份；
- 选择作用域：突发窗口、Map、Game、存档加载周期或进程；
- 输出最终抑制摘要；
- 有价值时保留可检查计数器；
- 在声明的生命周期边界重置。

进程静态的“前 N 次”限流可能隐藏后续存档问题。如果失败工作本身昂贵，限流不能代替熔断。

## 开发工具

Release 构建可以包含开发者模式操作，只要受到控制且服务于真实诊断。定义：

- 可用条件和所需游戏状态；
- 破坏性操作的前置检查与确认；
- 复现需要时使用确定设置或记录 Seed；
- 生成对象和临时状态的清理；
- 说明实际修改和失败内容的输出；
- 区分烟雾场景和断言。

有价值的工具可以创建代表状态、检查所有权/缓存/Patch、演练迁移或导出有界诊断摘要。只调用方法而不检查结果的按钮不是自动化测试。

## 故障处理

- 隔离可选参与者，避免一个 Logger、Observer、Handler 或 Debug Provider 停止其他参与者。
- 不静默捕获。刻意忽略失败时记录原因和足够上下文，使其可与成功区分。
- 逐帧/逐 Tick 日志必须去重。
- 日志级别关闭时，诊断格式化不得在热路径产生大量分配。
- 优先输出一份启动摘要，而不是数百条重复发现消息。

## 支持包

复杂 Mod 应能收集有界报告：版本/构建、启用 DLC 和依赖、相关设置、扩展状态、迁移版本、Patch 所有权和近期错误。删除凭据和用户内容。报告只描述观察状态，不应为诊断修改游戏。
