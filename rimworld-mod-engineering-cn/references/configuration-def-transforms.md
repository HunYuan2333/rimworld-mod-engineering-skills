# 配置与全局 Def 转换

设置会改变运行机制、代码会重写已加载 Def，或 Mod 会自动转换兼容内容时使用本参考。

## 配置生效契约

每个设置按安全生效时机分类：

| 类型 | 含义 |
|---|---|
| 立即生效 | 现有运行状态和 UI 可以立即原子更新 |
| 下次操作 | 仅新建工作、Projectile、Pawn 或命令使用新值 |
| 下次地图/游戏加载 | 必须在生命周期边界重建缓存或持久系统 |
| 仅新游戏 | 现有存档无法安全获得等价语义 |
| 必须重启 | Patch 集、程序集加载、Def 转换或静态初始化在本进程固定 |

在 UI 和代码中明确分类。复选框立即写入值，不代表功能能够立即生效。

每个设置定义校验、默认值、迁移、权威来源、变更通知、回滚行为以及是否改变存档语义。不要从 Draw 路径直接执行全局修改；应排队或标脏，在明确阶段应用。

## 转换管线

全局 Def 转换应定义有序阶段，例如：

```text
选择候选 -> 捕获基线 -> 验证 -> 生成计划 -> 应用 -> 重建缓存 -> 诊断
```

每阶段说明：

- 输入集合与所有权；
- 一次性还是可重复；
- 相对 XML Patch、Def 解析、其他转换器和缓存创建的顺序；
- 失败语义：原子、逐 Def 尽力而为或提交前中止；
- 能识别被转换 Def 和规则的诊断。

如果逐 Def 尽力而为是刻意选择，按 Def 隔离异常并输出有界摘要。不要留下半转换 Def。

## 基线与来源

共享 Mod 进程中的“原始值”含义不明确：可能是原版、XML 解析后、早期 Mod 修改后或首次应用时的状态。必须明确命名基线。

- 在声明阶段只捕获一次不可变基线。
- 重复应用不得覆盖基线。
- 冲突重要时追踪哪条规则修改了哪个字段。
- 明确重置是恢复捕获基线，还是按当前 Mod 组合重新计算。
- 不要假设恢复捕获值会保留其他 Mod 后续修改。

多个转换可能接触同一字段时使用确定顺序和诊断。小型 Mod 不需要完整来源图，但全局转换器应能解释最终结果。

## 幂等与缓存一致性

幂等转换执行两次与一次结果相同。可以使用标记、不可变基线、替换而非追加，或从权威状态重建。

修改后找出所有受影响缓存和派生数据库，在有文档的阶段重建。修改 Def 却不使消费者缓存失效，可能比转换直接失败更危险。

## 私有访问与版本漂移

必须访问私有字段时：

- 按精确类型、名称和签名只解析一次；
- 在任何转换前校验；
- 缺失或不兼容时可见地禁用该功能；
- 将访问集中在一个有版本锚点的适配器；
- 为支持版本提供启动诊断或聚焦测试。

不要把反射散落在设置 UI 和运行时代码中。

## 审查问题

- 设置的权威值是什么，何时生效？
- 每个重写字段的基线是什么？
- Apply/Reset 能否安全执行两次？
- 单个候选失败时发生什么？
- 哪些缓存需要失效？
- 如何发现或解释后续转换冲突？
- 运行存档中能否修改，现有对象如何处理？
- 禁用/移除 Mod 后，持久对象或全局状态是否失去定义？
