# 运行时状态、生命周期与存档

## 有意识地选择状态所有者

- `ThingComp` / `HediffComp`：状态属于单个已生成或持有对象。
- `MapComponent`：状态属于一张地图，地图销毁时应消失。
- `GameComponent`：状态属于当前游戏/存档。
- `WorldComponent`：状态跨地图并属于世界。
- 静态缓存：只保存可重建的进程状态，并在游戏切换时清理/重建。

不要把存档所有的可变状态放进全局静态变量。可以重建的缓存通常不应序列化，除非重建会丢失语义或成本不可接受。

静态状态必须标明作用域：

| 作用域 | 示例 | 必需重置点 |
|---|---|---|
| 进程 | 不可变元数据、反射委托 | 通常无需重置，但不得保留游戏对象 |
| Def 加载周期 | 已解析 Def 的索引 | 支持重新初始化时重建 |
| 游戏/存档 | 节流器、查找表、派生服务 | 新建/加载游戏及返回主菜单 |
| 地图 | 空间网格、网络索引 | 地图移除和游戏销毁 |
| 单次操作 | 递归守卫、事务上下文 | 在 `finally` 中清理 |

没有明确作用域的静态状态，即使暂时无害，也属于审查问题。

## 游戏对象所有权转换

Pawn、Thing、WorldPawn、Lord、Quest、Map 以及 Spawn/Despawn 状态参与游戏生命周期。将变化视为所有权转换，而不是简单修改集合。

每次转换记录来源所有者、目标所有者、合法中间态、持久化方式和清理路径。常见配对：

- Spawn / Despawn 或 Destroy；
- Register / Deregister；
- 加入 WorldPawns / 移除或交还丢弃决策；
- 永久保留 / 允许游戏回收；
- Subscribe / Unsubscribe；
- Acquire / Dispose。

从 Mod 列表删除 Pawn 并不会释放 `KeepForever`。销毁对象也不会自动清除指向它的缓存、字典键、事件订阅和存档引用。

审查少见退出：过期、拒绝、生成失败、任务/工作取消、地图移除、派系变化、回调中死亡、部分加载和 Mod 关闭。

## 持久化规则

每个持久化字段都应定义：

- 所有者和寿命；
- Scribe 模式（`Value`、`Def`、`Reference`、`Deep` 或集合模式）；
- 旧存档缺失字段时的默认值；
- 交叉引用解析后的有效性；
- Def、Mod 或 DLC 缺失时的行为；
- 从旧名称/结构迁移的方法；
- 引用对象销毁、未生成或移除后的清理。

需要已解析引用的修复放在 `PostLoadInit` 或更晚阶段。迁移应版本化、幂等并可观察。不要在会改变玩家语义时静默重新解释旧状态。

## 状态机与重入

工作、任务、长操作、网络请求和多阶段战斗行为应显式定义状态和合法转换。明确取消、超时、存读档、重试和清理，避免多个布尔值组合出非法状态。

递归或重入调用中的上下文应限制在当前调用链。优先传递显式上下文；否则使用栈、令牌或线程局部上下文，并在 `try/finally` 中 push/pop。单个静态布尔值无法区分嵌套，并可能在异常后泄漏。

## Tick 与集合工作

按 `实体数 × 频率 × 单次工作量` 估算成本。语义允许时采用事件驱动失效、错峰 Tick、空间索引或有界队列。不要仅为性能把正确性要求的原子工作改成尽力跳过；先确定语义。

遍历可变游戏集合时考虑回调中的移除和 Despawn。只有必要且经过测量时才复制，否则采用稳定遍历协议或延迟修改。

## 存档兼容声明

分别说明：

- 加入现有存档；
- 从每个支持旧版本升级；
- 临时禁用；
- 永久移除；
- 降级。

“成功加载一次”不等于迁移测试。执行“旧版本保存 → 升级 → 游玩 → 保存 → 重载”，并在承诺支持时测试缺失可选内容。
